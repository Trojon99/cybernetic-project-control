# 快速开始：先让一个 Agent 管理一小段工作

## 1. 先理解两份仓库

CPC 仓库保存方法与测试；你的科研/工程仓库保存真实项目。安装 CPC 不是把你的私人项目上传给 CPC，也不是让本包自动修改所有项目。

复制整个 `skills/cybernetic-project-control/` 到宿主的 Skill 目录，或给 Agent 一个明确的本地读取路径。按需加载 references，不要把全书或整个仓库一次塞进上下文。

## 2. 第一次使用只读建模

可直接给 Agent：

```text
使用 cybernetic-project-control 管理当前项目。
先不要改文件。读本项目已有说明、当前记录、主要产物和授权边界。
告诉我：
1. 项目现在可以确认什么，以及证据在哪里；
2. 什么仍不知道、什么可能已经过期；
3. 当前最关键的缺口；
4. 下一步建议及两个候选动作的取舍；
5. 做完后检查什么，哪些事情需要我批准。
复用已有项目记录，不要另造第二套状态库。
```

不要让 Agent 基于仓库文件名直接补写项目目标。缺失的目标应标记为待确认。

## 3. 一次授权，推进一段

确认目标和管理建议后，给范围授权，不用每一个小动作都问你。例如：

```text
允许你在本地实验分支内检查和修改代码、运行已有测试；最多推进三个有界动作。
不要更改核心目标、删除原始数据、增加云端费用、公开发布或操作真实设备。
每个动作预先写清验证方式；反馈未到时不要重复提交相同任务。
三个动作内完成、耗尽预算或触发重大问题时，保存状态并向我报告。
```

预算数字是用户选择的操作策略，不是控制论推导的最优参数。实际宿主权限仍优先。

## 4. 已有状态系统

已有 LoopX、APM、PSG、Notion 或自有文件时，先建立只读映射，保留一个权威写入者。不要先运行 `init`。参考 [集成总览](../integrations/README.md)。

完全没有持久记录，才考虑参考 adapter：

```bash
# /path/to/sandbox 必须是自己准备的试验目录
python tools/cpc.py init /path/to/sandbox \
  --project-id my-project \
  --objective "完成已约定的可复现演示" \
  --criterion "独立读者可以按说明复现演示" \
  --controller project-controller
python tools/cpc.py snapshot /path/to/sandbox
```

默认 advisory。初始化只创建 `.project-control/`，不改原有 `AGENTS.md`、代码或 Git 配置。已有明显状态系统时拒绝初始化；先由人决定映射或迁移。

## 5. 暂停与恢复

暂停时保存：实际做到哪、未成熟反馈、未提交修改、主要判断依据、禁止重复的失败条件、下一安全动作。不是全量聊天转储。

恢复时先检查记录是否仍然适用于当前版本、产物和权限，再继续。十天并不自动让所有证据失效；相关代码、数据、目标或环境变化才决定适用性。

## 6. 看不到和做不到的事情

不能看图就请宿主提供可读图像，不要只看文件存在就解释趋势。没有 SSH 工具，就不能读远端 Max；没有读写权限，就只生成建议。没有 scheduler，本包不会在你关掉电脑后自行继续。

## 7. 首次验收

先用仓库附带的三个合成项目。能正确识别一个瓶颈不代表已经学会全部项目管理；下一步跑配对行为评测，再考虑真实项目和更宽权限。
