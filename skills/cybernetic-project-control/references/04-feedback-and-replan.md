# CPC-06 / CPC-07 / CPC-10 / CPC-11：反馈有时间，重规划有代价

## 反馈成熟

提交实验/外部任务时记录 task_ref、预期反馈时间和超时复查点。反馈未到时等待，或做不依赖它且已授权的独立工作。别重复发同一任务。

超过复查点：先读现有 job/日志确认执行事实，再决定取消或重试。断网、没有回报和实际失败是三个不同状态。

## 预期与实际的差距

针对非平凡动作，先写预期观察，再执行。结果不符时依次检查：

- 实际执行是否不同于计划？
- 观测是否有噪声、错位、失效或遗漏？
- 外部条件是否改变？
- 原来的依赖模型或瓶颈判断是否错误？

不是每次失败都重试，也不是每次波动都改变研究方向。

## 防止反复返工

相同前提下重复失败且没有新信息时，应收缩范围或升级。方向 A/B 来回改却没有新证据时，检查目标不清、控制频率过高、接口耦合和测量问题。

稳定性在此是操作性启发，不是李雅普诺夫证明。不能为了减少“反转次数”而拒绝新证据驱动的合理逆转。安全问题或关键前提失效可以立即触发改变，无需等待固定次数。

## 策略适应

若多轮预测失配，提出“管理规则修改候选”：旧规则、新规则、适用范围、失败与反例、验证方案、回退条件。执行任务的 Agent 不可自动改验收标准、授权和 eval oracle 来让自己成功。

## 停止也是管理动作

达到验收；预算耗尽；关键反馈未成熟且无独立有益工作；真实权限缺失；继续工作没有合理价值；需要人确定目标。分别明确 stop/wait/escalate，不持续生成无意义 todo。
