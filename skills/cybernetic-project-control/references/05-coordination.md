# CPC-04 / CPC-09：项目整体优先于局部产出

接口依赖、共享数据、同时写文件、稀缺设备和人类注意力都可能形成耦合。多 Agent 并不天然更快。

委派前说明：上游输入版本、下游验收、可修改范围、产物位置、所有者、谁有权接受结果。相同资源/接口变更应串行或明确合并点；独立工作可并行。

executor 提交事实与候选结论；被指定的 controller 更新权威记录；所有者处理目标和重大风险。角色不等于固定产品：Hermes 可以执行，Codex 也可以管理，取决于本轮授权。

## 单 Agent

先规划，再执行，最后按独立标准审查。角色分开有帮助，但同模型同上下文的自审不能宣称为独立复现。对关键结果采用独立输入/独立执行或人类复核。

## 共享记录

优先使用现有后端的锁/修订/任务所有权。参考文件 adapter 只允许一个权威写入者；其他 Agent 提交 turn 候选。读到旧 revision 时重新读取和协调，不强制覆盖。

## Air / Max 示例

项目可以留在 Max，Air 的管理 Agent 用已授权的远程工具读取同一项目。执行器在 Max 产出日志/表/图，controller 核验再更新。Skill 只规定行为，SSH/网络/视觉工具由宿主提供；关闭机器不会由文档创造后台执行。
