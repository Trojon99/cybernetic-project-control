# 本次设计复核

**版本：0.1.0-alpha.1。** 这是同一制作流程中的复核记录，不是第三方审计。效果仍需真实 Agent 对照实验。

## 1. 比“管理任务”多了什么

核心对象是目标与证据之间的差距，而不是待办项数量。CPC 要求 Agent 在执行前说清：针对哪个必要条件，为什么现在做，预期何时看到什么，反馈不同会怎样改变计划。完成记录与更新科学/工程判断分开。

## 2. 把控制论落实成可观察决策

- **观察与状态估计**：状态只是有证据范围的工作性判断；不知道、过期、互相矛盾都允许出现。不能凭文件名或旧 Agent 的结论补成事实。
- **反馈与时滞**：待反馈任务有标识、预期时间和超时核对点。等待并不是失败；超时首先查运行事实，不重新提交到成功为止。
- **协调与整体目标**：检查接口、资源、依赖和长提前期，不用单个模块完成度代替整体验收。
- **有约束的行动**：先核对授权、资源、工具与硬限制，再比较信息价值和交付价值。没有量化依据时不伪造最优权重。
- **模型修正**：结果不符时，不仅问代码是否执行错，也问观测、外界条件和原来的管理判断是否错误。
- **稳定性启发与停止**：防止无新信息的反复改计划，但允许反证带来的合理逆转；达到验收便停止。这里没有数学稳定保证。

## 3. 源头约束

原书目录和选定正文重新核对；所有 Agent 规则都标为现代设计，不能倒灌成钱学森、宋健的原话。没有重新逐字审计整本书的所有公式。没有把全书扫描件或外部仓库实现放进发布包。

现有 APM、LoopX、PSG 和控制论治理 Skill 也涉及主动管理。本包只提出可检验的组合贡献，不以“别人只会记忆”作前提。

## 4. 工具为何保留得很小

可选 Python 工具只检查记录、产物字节、依赖和修订，随后形成有界更新。它不生成计划、不执行 shell、不运行模型、不调度后台任务。已有项目后端时直接复用，不强制迁入参考 JSON。

本地文件锁与 revision 处理合作式写入冲突，不声称是分布式协调。actor/reviewer 只是标签，宿主必须执行真实权限。

## 5. 本次复核发现并修正的问题

**已撤回证据仍可能被称为 checked result。** 现在先执行失效传播，再要求 checked result 所有直接证据引用均为当前已审查记录；新增回归测试。格式审查仍不等于科学验证。

**历史 receipt 的摘要可能与原记录不同。** 现在核对 ID、项目、修订、mode、actor、时间、摘要和 digest；检查时间单调性与 canonical receipt path。这不是签名，持有写权限的人仍可伪造整套记录。

**决定之间可能互相 supersede。** 现在只能替代列表中更早的决定，避免引用未来决定或循环。

**评分器输入可能有重复 JSON key。** 增加有限大小、非有限数拒绝、重复 key 拒绝；升级请求必须包含具体问题。仍只做选择/引用格式检查，不能评价真实行动或解释正确性。

**真实用户创建 .venv 后，仓库检查可能误扫第三方依赖。** 检查器与打包器明确排除虚拟环境、缓存、真实运行和私有评测；新增测试。

## 6. 故意不在此版本声称完成的事

跨 Agent 能力提升；macOS 实机环境；Hermes/Max SSH 和视觉；LoopX/PSG/APM 写入；自动后台连续工作；真实身份认证；秘密检测；科学结论认证；GitHub 远程发布。

## 7. 下一步验收，不是下一步扩容

先冻结此包，在隔离项目副本中比较强通用 PM Skill 与 CPC。重点看有没有减少重复干预、漏看依赖、无谓返工和人工逐步调度，同时不增加无价值的记录和调查。若没有改善，删改规则；不要先增加更多层、术语和服务。
