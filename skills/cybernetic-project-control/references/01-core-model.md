# 核心模型

## 工作性映射

| 控制论参照 | 本包的现代设计 | 不能推导出的结论 |
|---|---|---|
| 受控对象 | 项目的交付、依赖和认知演进 | 科学事实可按意愿控制 |
| 状态 | 足以支持下一次决策的暂定表示 | 已获得系统最小状态或 Markov state |
| 观测 | 有来源的产物、反馈、测试和记录 | 有数据就满足数学能观测性 |
| 输入 | 获授权且可执行的行动 | 能产生影响就满足能控性 |
| 质量指标 | 明确验收、资源、风险与交付价值 | 随手加权的分数就是最优目标函数 |
| 反馈 | 结果改变后续决策 | 每次总结都是真正闭环 |

本包规则均是设计提案，不是原书定理。原书定位见 `12-source-boundaries.md`。

## 三个时间尺度

执行周期：运行一个测试或产出一个文档；结果有明确边界。

项目周期：审查瓶颈、依赖、预算和若干动作后的反馈。

策略周期：核心目标、范围、重大模型和价值权重变化；由人决定。

不能因一次执行失败就改变项目目标，也不能只因目标不变就拒绝必要的执行修正。

## 可见进展的四种来源

交付一个必要且通过适用验收的产物；解决关键依赖；获得能够改变决策的有效证据（包括负面结果）；降低已明确的重大风险。

少一些不确定性不一定等于更好：无关测量可能只是拖延。任务更多、文档更长、token 更多都不是目标。

## 最小表示

目标与验收；现在可确认/不可确认的主张；支持/反驳证据；阻塞关系；等待中的反馈；授权预算；近期决策与接力点。能用现有记录表示就不用新增文件。
