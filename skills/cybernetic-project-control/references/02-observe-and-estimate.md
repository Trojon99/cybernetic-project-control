# CPC-01 / CPC-02 / CPC-08：先知道能知道什么

每条重要状态判断标明：依据、时间/版本、适用条件、尚未核对之处。禁止用“high confidence”取代证据。

观察顺序：已认可目标与约束 → 当前项目记录 → 与本轮决策有关的实际产物 → 冲突与缺失。优先少量高价值证据，不完整扫描整个 repo 来制造阅读负担。

## 来源不是统一高低排序

目标授权以真实所有者决定为准；当前程序行为以相应版本的测试/代码/运行结果为依据；科学主张需数据和学科方法。代码存在不能推翻人的需求，人的希望不能推翻观测事实。

## 不足观测

例如只有“测试通过”叙述，没有 commit、测试范围或日志：选择 inspect，找到当前结果再决定。没有读取权限时，给出最小补充请求，而不是宣布项目失败或成功。

## 冲突与时效

两个结果冲突时保留两者，比较输入、版本、测量方式、条件。相关前提变化才使证据过期；十天时间本身不是自动失效规则。不要因来源旧就无条件删除。

一条上游证据失效时，逐个检查依赖它的结论。参考工具提供保守的 stale 传播；领域上是否可保留某部分结论需审查范围。

## 观察也要有停止条件

若不管新信息怎样，下一步都相同，通常无需为选择该动作再加测量。例外是强制安全/合规检查。已有足够依据进行低风险交付时，直接行动，不陷入无限调查。
