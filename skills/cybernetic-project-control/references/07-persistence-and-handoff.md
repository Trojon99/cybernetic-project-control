# CPC-01 / CPC-09 / CPC-12：记忆作为输入，管理作为能力

先寻找已有权威记录。CPC 的逻辑概念可映射到 Git 文件、LoopX、APM、PSG 或其他系统，不要求新建文件名。

首次接手：确认 source_of_truth 和写入权；读取必要状态；核对关键产物与工作区变更；标未知；提出下一步。无法访问旧资料时明确缺口，不制造完整历史。

停下来保存：当前目标版本；已确认/未确认事实；关键决策与适用前提；待到达反馈；未提交修改/分支；失败路径及不再适用的条件；下一安全动作和需人的决定。

不要保存所有聊天或自动导入敏感数据。保留链接/哈希/决定理由优先于复制整份原始材料。

新 Agent 恢复的是记录，不是原 Agent 的全部技能。还需要领域能力、工具权限和适当观察。相同 Skill 也不保证相同模型判断。

## 参考文件模式

`.project-control/state.json` 加 `receipts/` 是 0.1 的测试/试用实现，不是强制协议。状态是唯一当前投影，receipt 只有被 history 引用才算接受。单写入者；不在两台机器各写一份后指望 Git 自动解决语义冲突。

## 正常回滚

代码可按既有 Git 流程恢复；知识记录不抹去失败事实，而是标记撤回/失效和替代决定。恢复旧快照不能让旧证据自动适用于新目标。
