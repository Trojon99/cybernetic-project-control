# 效果验证协议

## 不能把什么算成证明

单元测试通过、oracle 自测通过、案例中选中了正确字母，都不证明真实 Agent 已获得通用项目管理能力。公开案例是开发回归素材，答案可见，不是私有 held-out benchmark。

## 研究问题

在同样模型、宿主工具、项目状态和预算下，CPC 是否改善管理决策、减少无效工作/权限错误，并保持交付速度？改变的是 Skill，不能把同时换模型或多花数倍 token 的收益全部归给它。

## 基线

A 无 Skill；B 仅项目记忆/接力说明；C 强通用 PM Skill（含主动规划、风险和重规划，不能故意设弱）；D CPC。另做消融：移除观察不足、时滞、耦合或策略更新规则中的一项。APM/LoopX 等完整系统可做独立 system comparison，不冒充同工具条件的纯 Skill 效应。

仓库内 baselines 是起点，不宣称 token 长度已匹配。用实际模型 tokenizer/usage 记录上下文、输出、工具、墙钟和人工介入；设计同预算与可比指令长度条件，不用重复填充文本“凑长度”。

## 两层测量

**公开判断 fixtures**：给出观察、候选动作；自动检查选择、mode、引用是否来自可见证据，以及是否违反硬边界。`run.py score` 只做这层检查。

**轨迹/真实项目任务**：在隔离项目副本中执行多个阶段，按阶段开放新反馈，观察是否改变计划；包含实际执行失败、延迟、证据撤回、权限请求、停止和交接。人工审查内容与真实产物，记录成本和完成结果。

## 避免答案泄漏

`prepare` 仅复制 case context/observations/options/request/response schema，剥离 oracle。把它输出到**独立沙箱**；受测 Agent 不能访问 evals/cases、评分器源代码、oracle、之前结果或其他组输出。需要的 Skill 作为单独文件包提供，不能暴露整个评测仓库。剥离不等于沙箱，访问隔离由实验者负责。

开发项目和测试项目按项目划分，不把同一项目的轻微改写分到两边；冻结 Skill 版本后，再由独立人员构造未公开项目/扰动。`evals/private/` 不进入公开 release。

## 配对与重复

同一案例在各条件下用独立干净会话；随机化案例/条件顺序。多个独立重复，记录温度/seed（若支持）。至少研究和工程两类，多种 Agent/模型规模；同一模型两个壳不等于跨模型泛化。

先约定错误分类与主要指标，不在看到结果后只报告有利指标。预先确定次数/预算、失败和超时如何计入，避免反复跑到显著才停。

## 主要指标

有依据的下一动作；核心依赖识别；实际产物与解释一致；对反馈与新信息的合理反应；无效重做；必要的人类升级与不必要升级；授权违规；交付/资源成本。

不是单看回答长度、任务数、token 数或文件数。科研案例不以显著结果为成功。

## 人工盲评

评分者不知道条件和 host 名；每项 0/1/2 分：事实依据、取舍质量、反馈分支、权限边界、项目价值。总分不是唯一结论，硬性权限错误单独报告。用两名评分者记录分歧并保留裁决理由；同模型给自己评分只能算辅助，不是独立评审。

## 报告

提供逐案例结果、paired 差异与不确定性区间；小样本报告范围和全部失败，不声称显著普遍改进。保存 model/host 版本、Skill 哈希、输入哈希、时间、工具权限、预算与实际消耗、人类介入、原输出与评分。公开前脱敏。

当前本包**没有真实模型评测结果**。自动 fixture 检查是验证评分器与文件 contract，而不是给 CPC 自评管理能力。
