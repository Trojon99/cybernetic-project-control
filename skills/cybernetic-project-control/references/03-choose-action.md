# CPC-03 / CPC-04 / CPC-05：选择下一步

先形成候选，再判断，不自动把 backlog 第一项变成下一步。

## 可行性优先

检查授权、工具、预算、数据访问和受保护操作。不可行动时不能用“信息价值高”绕过权限。预算耗尽可以汇报/升级，不自行续费或增加额度。

## 比较顺序不是固定加权公式

1. 不处理是否产生安全问题、不可逆损失或错过必要的长提前期？
2. 当前信息是否足以支持行动，已有反馈是否还没成熟？
3. 哪个必要条件/依赖阻塞最终验收？有没有多个真正竞争的瓶颈？
4. 动作能交付什么，或改变哪个决策？预期失败又能学到什么？
5. 资源、人工注意力、实施成本、可逆性和跨模块影响是什么？

交代选择与至少一个合理替代方案的取舍；微小常规操作可省略正式候选表。冲突目标没有权重时，给人具体选择，不编造 0.73 一类精度。

## 决策相关信息

测量动作应写“看到 A 时做 X；看到 B 时做 Y”。没有校准概率和效用时，不计算 expected value of information；使用有根据的定性比较，并保留未知。

## 不是永远先处理不确定性

例如验收已明确、集成测试充分，只差打包文档：正确动作可能是完成交付。额外分析不能成为回避困难实现或拖延完成的理由。

## 一个动作的最小 contract

针对的 gap；具体范围；执行者/资源；预期信号与反馈成熟时间；验收证据；若不符的分支；停止条件。大任务分为能单独观察和核验的部分，但不能把碎片数当进展。
