# 输出 contract

## 给人的五项管理回报

当前事实；关键缺口；下一动作及取舍；反馈/检查分支；权限和交接点。用能理解的项目语言，除非有必要，不展示控制论术语。

## 对工具/执行器的任务要求

目标与上游版本；处理哪个问题；范围和禁止动作；产物/证据；预期信号与反馈时点；资源上限；停止条件；返回结构。已有后端格式优先，不强制换成 CPC JSON。

## 返回的事实

执行状态、实际变更、可访问产物、测试/观察、局限、异常、下一候选。不要仅返回 done；不要把“生成文件”写成“科学主张已证实”。

## 接受状态更新

新证据与既有证据分开；矛盾保留；失效传播；明确判定适用条件。普通 turn 不改目标、验收、授权和预算。跨 Agent 交接需要 source_of_truth、revision 和实际访问路径，不是聊天摘要里的模糊标题。

## 参考 JSON contract

state 是暂定状态快照；turn 是一次管理判断及反馈记录；receipt 是被接受 turn 的不可变副本。Schema 和工具帮助检查低级矛盾，不证明优先级最优或科研结论正确。初始模板有 unknown，而不是伪造完成。
