# 范围与验收

## 必须有

R1 跨项目方法：科研和工程为核心，软件与学习作为 profile，不依赖经济学变量。

R2 主动管理：能提出有依据的下一步，含执行、观察、等待、协调、重规划、升级与停止。

R3 控制论可追溯：来源主题 → 现代映射 → 行为规则 → 正例/反例 → 测试。

R4 证据诚实：事实、解释、执行状态、研究主张分开；失效证据不能继续支持当前主张。

R5 有界自治：预授权可连续执行；重大变更不能由 Agent 自己批准。

R6 可暂停与换 Agent：复用既有项目记忆，恢复前检查新旧状态；不能保证凭空获取缺失上下文。

R7 可移植：复制整个 Skill 即可阅读和执行其方法；不依赖根目录理论文档或外部服务。

R8 可检查：Schema、输入安全、revision、重复提交、证据冲突/依赖/哈希有自动测试。

R9 可证伪：公开开发案例、明确 baselines、可消融的机制、逐任务失败与成本统计。

## 不在 0.1 范围

生产执行器、跨机锁、Agent-to-Agent transport、调度、自动联网、云 API、模型训练、隐藏后台工作、真正的权限认证、完整科学审稿系统。

## 完成标准

工程完成：包可读、单测和文档检查通过、三类例子可检查、演示可复跑、状态边界写清。

效果完成：尚未达到。需真实 host/model 在相同条件下相对 baselines 的配对试验。

发布完成：尚未达到。需仓库所有者检查内容与许可并决定远端、可见性、首个 release。
