# 设计论证：控制的是项目行动与认知，不是“获得想要的科学结论”

## 1. 问题定义

CPC 的输入是项目目标、现有状态记录、可访问证据、工具能力、资源预算和授权。输出是一个可解释、可验证、有边界的管理动作，以及该动作后如何更新判断的规则。

核心不是再存一份状态，而是学习一个操作策略：什么时候继续执行，什么时候先观察，什么时候等待已有反馈，什么时候重新规划，什么时候停止或交给人。

我们拒绝将“别人只会记忆、我们才会管理”作为产品事实。APM 与 LoopX 等已经主动管理和重规划；CPC 必须通过对照才能说明增量价值。

## 2. 三种不同的状态

- **现实项目状态**：真实需求、系统行为、数据质量、科学事实。通常不能完全观察。
- **工作性状态估计**：Agent 根据证据形成的暂定判断，有范围、时效、未知和矛盾。
- **管理记录状态**：哪个动作在运行、谁获授权、什么决定被接受、预算还剩多少。

“权威记录”只表示团队约定的操作依据，不表示科学上的绝对真相。状态估计可以降级；负面结果可以推进研究；执行完成可以不推进任何关键目标。

## 3. 四个控制职责

### 观察者

从当前产物而不是叙述恢复证据，检查版本、来源、有效范围、缺失通道。观察不足时，优先选择会改变下一步判断的测量，不凭空给项目打一个百分比分。

### 有界控制策略

先筛掉未授权/不可执行的动作，再比较安全、关键依赖、长提前期、决策相关信息、交付价值、成本和可逆性。使用明确的取舍，而不是无依据的加权分数。必要时保留多个候选让人确定价值权重。

### 模型检查与适应

对非平凡动作，在执行前记录预期信号和失败分支。反馈到了才比较。预测失配时，同时考虑执行错误、观测失效、外界变化和管理模型错误，不只让执行器重试。

### 人类监督

人定义研究价值、目标和不能跨越的边界；Agent 可在预授权范围内自主管理。改变目标、接受重大未解决风险、公开发布、不可逆修改等需要更高权限。这里不是每个本地任务都重新请示。

## 4. 不把每一步都叫“数学控制律”

可以用示意式表示设计：

\[
\hat{s}_{t}=\mathcal{O}(E_{\le t}, D_{\le t}),\qquad
 a_t=\pi(\hat{s}_t,G,C,B,P_t),\qquad
\hat{s}_{t+1}=\mathcal{U}(\hat{s}_t,a_t,E_{t+1}).
\]

其中 E 是证据，D 是决策记录，G 是目标，C 是约束，B 是预算，P 是等待中的影响。这里 O、π、U 是程序性职责，不是原书中的现成方程，不保证马尔可夫性、完备观测或可证明最优。

目标与状态常含类别、逻辑条件和文本，不能直接写成数值 `x* - x` 再计算“误差”。采用“未满足的验收条件及其依赖”作为工作性差距。没有清楚概率模型时，也不声称算出了信息熵或最优信息价值。

## 5. 更高一层不等于再建一层软件

执行层回答“按要求运行了吗”；项目层回答“这一结果改变了哪项决策”；策略层回答“目标、假设或资源权衡是否应调整”。层次是职责和权限，不是强制增加 Agent 数量。

CPC 只提供项目层/策略层的可执行规则，调用宿主已有工具。单 Agent 可按阶段完成，但同上下文的自审不能标为独立复现。风险较高时应采用隔离输入的第二审查或人类专家。

## 6. 主要工程取舍

- 核心 Skill 小、references 按需加载；弱模型采用最小控制卡，而不是强塞所有理论。
- 先复用已有状态系统；参考 JSON adapter 只服务测试和无基础设施的试用。
- 状态写入集中到一个被指定的 controller；executor 提交结果，不能自行宣布主张成立。
- `revision` 防止合作式写入者覆盖彼此。外部后端的 revision/lease 由后端负责。
- 策略避免重复干预：反馈未成熟不等于失败，超时也不等于任务一定没运行。
- 无新证据的反复改计划需要检查；有新证据的合理逆转必须允许。
- 元学习不得自行降低成功标准、扩大权限或修改评测答案。

## 7. 为什么还有代码

小工具只校验约定、验证本地产物字节、形成有修订号的记录和准备评测。它不是计划生成器、调度器、状态数据库或工具执行器。删除这些工具，Skill 仍然可使用；保留工具，部分低级错误可自动发现。

## 8. 当前不能宣称

不能宣称“任何 Agent 都学会”“长期项目稳定收敛”“科学结论可自动认证”“我们优于 APM/LoopX”“已经兼容所有 runtime”。这些均需要实际模型实验或数学条件，不由本仓库存在自动推出。
